# HTTP 文件收尾

[English](http-publication.md)

从 0.3.0 开始，普通 HTTP/FTP 文件由 taiji 完成收尾。配置
`http-incomplete-suffix=.motrix` 后，下载写入 `name.ext.motrix`，最后一次
改名为 `name.ext`。所有下载模式，包括不支持 Range 和未知长度的响应，
都先验证用户指定的校验和、同步文件并关闭句柄，再发布最终文件。

## 完成状态与重试

收尾期间，`http_task` 持久化状态为 `finalizing`。
`config_json.publication` 保存实际源路径、已选目标、预期长度、
预留标记、阶段和最近错误。已关闭的输出不占下载并发名额，下载并发设为零时
也能继续收尾。文件临时被占用或磁盘暂时不可用时，重试文件操作，不重新探测
或下载网络资源。只有发布成功，任务才进入 `done` 并发送
`taiji.onDownloadComplete`。

普通路径使用禁止覆盖的原子改名。下载期间出现重名文件时，选择带编号的新名字，
先保存路径再操作。只要源文件还存在，就不会因为目标大小相同而把别人的文件当作
下载结果。不支持禁止覆盖的改名时，依次尝试硬链接、同目录独占创建并持久化的
目标预留文件。预留降级面向应用管理的目录，不能防止不受约束的外部写入者在检查后
替换预留文件。

普通完成和恢复不要求文件标识、卷 UUID、旁路进程或第二遍全文件哈希。不支持目录同步时记录降级信息并继续，
包括 Windows 对目录句柄的访问拒绝；文件同步失败和真实磁盘、传输故障仍然保留
待处理状态或报错。硬链接发布成功后，残余源链接清理失败不会阻止最终文件可用。

## 固定宿主接口

需要运行收尾前插件的任务设置 `http-host-finalize=true`。引擎关闭文件句柄后，
持久化 `ready` 并发送 `taiji.onHttpOutputReady`。宿主必须读取实际路径，不能用
最初的文件名推算。`tellStatus.http.hostControlled` 允许宿主在自己的数据库事务
提交前保持逻辑上的 Finalizing 状态。

- `taiji.getHttpOutput(gid)` 返回字符串字段：`state`
  （`downloading|ready|publishing|published`）、`hostControlled`、`paused`，
  以及可用时的 `sourcePath`、`finalPath`、`length`、`error`。
- `taiji.finalizeHttp(gid, {action, path?})` 支持 `publish`、`external`、`hold`，
  路径必须绝对。`publish` 持久化接受发布请求，重复调用沿用已接受的意图；文件操作
  由下载驱动执行，不占用会话命令循环。`external` 只在宿主的特殊替换或移动事务
  已提交文件和数据库后确认结果。`hold` 取消并等待正在执行的发布操作结束，保留
  回执，供删除任务前读取实际归属路径。
- 宿主在一个逻辑事务中提交实际路径、文件引用和完成事件，再调用
  `removeDownloadResult`。发布回执在移除前一直保留。启动、重连以及逻辑任务仍为
  Finalizing 时查询回执，弥补通知丢失。

暂停保留收尾意图。强制移除先取消任务并等待正在执行的发布操作结束，再确认移除。
已进入文件系统的操作不会因为取消异步任务就自动撤销。

## 恢复

下载驱动在创建 HTTP 客户端前恢复原样保存的收尾记录。启动保护在宿主恢复任务
所有权前限制放行。ready 任务等待宿主接受发布；已接受的操作重试保存的目标；
已发布的回执等待宿主数据库提交。无需推断文件名，也不重新传输数据。

| 中断位置 | 恢复方式 |
| --- | --- |
| 尚未持久化已关闭文件的收尾意图 | 按下载检查点恢复 |
| 已 ready，宿主尚未接受发布 | 恢复 ready，运行当前允许的插件 |
| 已接受，尚未改名 | 重试已保存的发布意图，不重跑插件 |
| 已改名，日志尚未清除 | 确认源已消失、目标长度符合记录，重试目录同步 |
| 原生发布成功，宿主数据库提交失败 | 只重试宿主逻辑事务 |
| 宿主数据库已提交，回执尚未移除 | 重试或下次启动时清理回执 |

Motrix 对没有实际插件贡献的普通任务、同目录改名使用原生收尾。插件确实修改元数据、
替换文件，或需要移动到其他目录时，保留宿主的持久化特殊事务。因此，下载过程中启用
插件仍然有效，普通文件生命周期也不再由两边重复管理。
